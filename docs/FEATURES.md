# Feature reference

Folder skill imports and updates refuse protected source folders, including aliases that point to private application or credential storage. Protected files within a source folder are also refused. Choose an ordinary skill source folder.

A complete tour of Arco capabilities, with links to subsystem contracts and
controls. For installation and first session, see
[Getting started](GETTING_STARTED.md).

## Workspace start and clusters

| Feature | What it does | Details |
| --- | --- | --- |
| Tabbed multi-provider workspace | Every project is a tab with one long-lived primary agent the operator chats with directly | Providers: Claude, Codex, Cursor, Ollama, llama.cpp, LM Studio, Strata, DeepSeek |
| Home | Start page for project locations, bookmarks, and open work | Greeting and status, start tiles, and Continue and Projects each limited to two rows of cards with Show all opening the rest (search and the location filter list every match); a Getting started card that counts any chat, session or cluster as started and can be hidden; stable project identity across relocation; cards can be pinned, archived, opened, or continued. See [Getting started](GETTING_STARTED.md) |
| Waiting questions | Marks structured Codex and Claude Native questions until settled | The toast opens the asking worker; cluster cards and tabs show a question indicator. |
| Workspace Outputs | Collects artifacts, generated-file events, and scoped exports | FILES tab **OUTPUTS** sub-tab for the active workflow or cluster. By default it shows what was made for you (generated media, top-level artifact documents, reports and exports); code edits and files in artifact subfolders sit under **All files**. **Save a copy** and **Move** can use an ordinary home folder or an approved project or media folder; on systems with POSIX permissions **Save a copy** writes an owner-only file; the result stays in the dialog; **Download** is a button. MOVE TO PROJECT reviews a copy or keeps the artifact private; large binaries are scanned for readable text only and listed as not fully scanned, as are files past the findings limit. Folder browsers and content dialogs open at sizes suited to their content, scale with the window, can be resized, and remember the chosen size (**Reset size** restores the default). Large artifact warnings offer KEEP or DISMISS; a kept artifact shows **Kept** with **UNKEEP**. See [Outputs](OUTPUTS.md) |
| Clusters | Multi-member coordinated work | Seven size-ordered templates (Pair through Large team) plus Build my own; at most one director on new work; work size only for repeated roles; member cards default to **ROWS**; AUTO-PICKUP modes Off, Rule-based (recommended automatic), Smart Observe-only, and Smart Automatic. Smart modes need an evaluator on Claude Native, Cursor, Codex, Ollama, LM Studio, llama.cpp, Strata, or DeepSeek through Xolotl. See [Getting started](GETTING_STARTED.md) and [Task ledger](TASK_LEDGER.md) |
| One status per tab | Shows at a glance which tabs need you | Workflow and cluster tabs show a dot when not idle (hover for the status); Home Continue cards show a word: Working, Needs you (a question waits, or an idle cluster member has mail), New reply (a turn finished while you were elsewhere; cleared when you open the tab; not saved across reloads) or Idle |
| Waiting mail on member cards | Shows undelivered messages per member | The member card's mail mark shows the count, delivered at the member's next turn; muted while the member is busy; highlighted when it is idle with mail, and clicking it nudges that member, after which the card reads Nudged (and the composer NUDGE button reads NUDGED n) until the member starts its turn or two minutes pass. No sounds or pop-ups |
| Needs you and board accept | Shows what only the operator can clear on a cluster board | **NEED YOU** above the member cards counts review tasks with a director sign-off, tasks blocked on an operator decision, and members waiting on an answer. On the Board, **ACCEPT** replaces DONE on review cards; **ACCEPT ALL MET** accepts met sign-offs; done tasks show by default (**SHOW DONE** hides them, and the choice is remembered) and the header count matches the tasks drawn; an optional release label on a task (RELEASE in the card drawer) adds a release filter and a ready-to-release summary (in, accepted, left); review tasks older than seven days fold into an older row. Optional Settings > Agents and clusters **Board auto-done** marks met tasks done automatically. See [Task ledger](TASK_LEDGER.md) and [Settings](SETTINGS.md) |
| Utility agent | One operator-chosen provider and model for short side jobs | Settings > Agents and clusters (also offered on the last Welcome screen). Accepts only Claude with Native sign-in, Cursor, Codex, Ollama, LM Studio, llama.cpp, Strata, or DeepSeek through Xolotl. LM Studio, llama.cpp, Strata, and DeepSeek require the chosen model to be loaded; these requests never load or switch models. Replies that are cut off or exceed the limit are reported instead of used. Never chosen silently; **TEST** checks it; **USE UTILITY AGENT** can fill it into Smart AUTO-PICKUP, Research, document edit, and handoff summarizer pickers without changing saved choices. See [Settings](SETTINGS.md#utility-agent) |
| BRIEF | Short synopsis from visible activity facts | On each member card and in the composer toolbar; in a cluster tab the composer's BRIEF offers THIS WORKER or WHOLE CLUSTER. Uses the utility agent; lists the facts; sends nothing to any worker. |
| CATCH ME UP | Summary since the last visit or operator message | On a workflow or cluster; the utility agent writes the synopsis for the covered time range. Empty ranges offer SINCE LAST TURN, LAST HOUR and TODAY without a model call. A failed summary stays in the dialog, not in chat. Unloaded or Incognito cluster members are skipped with a note. |
| TIDY | Rewrite the composer draft into a clearer instruction | Workflow and Chat composers. **ACCEPT** only replaces the draft; TIDY never sends. **KEEP ORIGINAL**, the close button in the dialog header and Escape leave it unchanged. |

## Context, handoff, and goals

| Feature | What it does | Details |
| --- | --- | --- |
| Context usage monitoring | Worker header shows `CTX: NNK / NNK NN%` color-coded against the model window | Claude CLI: CLI session latest context snapshot with JSONL byte-size calibration fallback; Claude Native: `messages.countTokens()` on the retained next-turn prompt; Codex app-server: latest per-call token snapshot from the rollout file. Codex tabs default to the account **MAX** context window (from `$CODEX_HOME/models_cache.json`; CONFIG can switch a tab to STANDARD); denominator prefers the provider-reported window, then that catalog estimate. Native compact clears stale Codex context fill until the next real snapshot |
| Auto-handoff after N compactions | When enabled, build a handoff and rotate to a fresh session after N compactions in one conversation | Off by default; default N is 5 (1 to 20). Per-tab in CONFIG, with Settings > Agents and clusters > Auto-handoff defaults for new tabs. Counts Claude Native and Ollama auto-compactions, Claude CLI compact boundaries, and Codex app-server compaction; Fold is not counted. Cursor and Codex exec cannot count, so the control is unavailable there |
| Context management and Fold (Claude Native) | Deterministic history trim in the same session | **FOLD** composer button trims older history into a digest while keeping a verbatim recent tail; no model round (cheaper than Compact) and no fresh worker (cheaper than Handoff); raw transcript stays in `events.jsonl`. **AUTO-FOLD** in CONFIG (off by default) fires when the budget crosses **FOLD AT**. A Fold is not counted toward auto-handoff. Per-turn token-budget meter and tool-result eviction keep large tool outputs from blowing the window |
| Turn time and activity times | See the current turn duration and when activity occurred | While busy, TURN appears at the right of the NORTH STAR row in a tab or cluster member pane. Single-tab and cluster ACTIVITY rows show local clock times. After a browser reload, the turn timer starts from the reconnect state. |
| North-star objective | Pin a durable free-text goal per tab | CONFIG -> NORTH STAR, `/goal <text>` composer command, or the always-visible NORTH STAR chip above the composer. Folds into the system prompt on every turn on every transport; inherited by Review / Handoff / Spawn; operator-write, model-read-only, byte-capped, with an anti-autonomy trailer; no tool can mutate it |
| Goal run | Arms a per-tab continuation loop toward the north star | `/goal run <n>` or CONFIG; one deterministic continuation turn after each settled turn, up to `n` iterations (default 10, max 500). Stops on budget spent, turn error, provider throttle, context >=92%, or cleared north star; **RUN n/N** chip is one-click stop. Continues because budget remains, never because a model judged work unfinished. Not persisted across a server restart. See [Gotchas: goal run](GOTCHAS.md#goal-run-north-star-auto-continue) |
| Ultracode mode (Claude) | Sticky per-tab Claude CLI orchestration mode | **ULTRACODE** composer pill pins the tab to Claude CLI at `xhigh` effort with multi-agent **Workflow** orchestration armed so one turn can fan out and coordinate subagents; live **FLEET** panel shows running/done subagent count; per-tab web-lookup budget bounds research spend. Operator-armed and sticky until toggled off |
| One-click handoff | Fresh session in the same tab seeded from a structured handoff | Choose **HANDOFF** for an unrelated task, a worker on a wrong track, a provider or model switch, or a provider without compaction. Compaction is lossy but has no fixed limit; plans, board, goal, artifacts and Git remain outside the conversation. **QUICK** builds a deterministic seed; **ORIGINAL WORKER** writes a reflection; **FRESH SUMMARIZER** uses a separate worker. Seed messages collapse to a one-line `HANDOFF SEED / click to expand` pill |
| Spawn from here | Fork the conversation to a new tab | The agent self-reflects with session context and Arco saves its reply as a handoff; the new tab opens with that document and an optional `new direction:`; the original tab continues in parallel |

## Safety and resilience

| Feature | What it does | Details |
| --- | --- | --- |
| API resilience | Catch and retry Claude CLI overload envelopes | `overloaded_error` and `{"type":"error"}` surfaced as a system notice; retried with 15s/30s/60s backoff up to 3 attempts (same session id, idempotent) |

| Review safe-mode gate (Claude Native) | Pause sensitive tool calls for operator review | Operator-armed per-tab gate (CONFIG -> REVIEW SAFE-MODE, default off) on `Bash`, `KillShell`, writes outside the project, `git push` / `reset --hard` / `clean -fd`; editable proposal card for review, edit-then-approve, or rejection. Durable across server restart; standing "approve all like this" with live re-evaluation against a non-lossy signature |
| Project-trust gate | Suppress untrusted project instruction files until trusted | Freshly opened or cloned repo `CLAUDE.md`, project skills (`.arco/skills/`), and `.arco/settings.json` suppressed until trusted. Composer shows UNTRUSTED PROJECT with **TRUST** / **NEVER**; decision in `~/.arco/trust.json`, reversible |

## What Arco explicitly does not do

| Rule | Meaning |
| --- | --- |
| No silent autonomous routing | Arco never picks models, providers, effort levels, or task completion without an operator-armed surface and an inspectable event trail |
| No hidden orchestrator authority | No meta-agent owns a workflow. Model-assisted decomposition, assignment, recovery, or synthesis is eligible only as a visible proposal or through bounded task tools the operator enabled |
| No hidden auto-synthesis | Review, SECOND OPINION, and Research outputs remain separate artifacts. Any synthesis is an operator-chosen bounded action or a visible proposal for inspection before applying |
| No LLM-curated project memory that edits itself | Knowledge/codebase memory is operator-triggered and operator-reviewed; session traces do not rewrite project instruction files |
| No opaque "smart" anything | Automatic or model-assisted behavior must be operator-armed, bounded by readable mechanics, logged, and reversible; existing cluster automations are off by default, deterministically capped, logged, and reversible |
