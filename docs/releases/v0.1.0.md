# Arco v0.1.0 release notes

These notes describe the first public Arco release candidate. A `v0.1.0` tag remains pending the checks below and the operator's approval.

## Arco

Arco is a local software workbench for project-aware conversations with provider-backed agents. It brings chat, project folders, terminals, files, Git, saved work, clusters, review tools, and optional voice into one browser interface. Providers and model accounts are configured separately; Arco does not bundle an AI model or account credentials.

## Platforms and installation

Native installation targets Linux, macOS, and Windows. Install Node.js 24 or newer, npm, Git, and Python 3 plus a C/C++ toolchain if a native dependency must compile. Keep `NODE_ENV` unset while installing. Clone the repository and run:

```sh
git clone https://github.com/ghreprimand/arco.git
cd arco
npm ci --include=dev
npm run build
npm start
```

Open <http://localhost:3001>. The [README](../../README.md) has platform-specific prerequisites and troubleshooting.

A Docker image provides an isolated server with a persistent Arco home and explicitly mounted project folders. Copy `.env.example` to `.env`, create the sample project mount, and run:

```sh
cp .env.example .env
mkdir projects
docker compose up -d --build
```

The [Docker guide](../DOCKER.md) covers Windows path setup and other mount options. The [Getting started guide](../GETTING_STARTED.md) walks through connecting a provider, choosing a project, and starting a conversation.

A new native installation with no projects or connected providers opens Welcome to Arco. The setup adds a project folder, connects a provider through Connections, then opens a prefilled workflow creator. Each step can be skipped, and setup can be reopened from Settings. Docker users sign in to a provider from inside the container and use mounted project folders.

## Providers and features

Available provider integrations include Claude, Codex, Z.ai, Gemini, Cursor, Antigravity, Ollama, LM Studio, llama.cpp, Strata, and DeepSeek through Xolotl. Account access, installed command-line tools, model availability, billing, and local service configuration vary by provider. The [provider guide](../PROVIDERS.md) lists transport and feature boundaries.

The workbench includes Project Home, saved and Incognito conversations, an embedded terminal, a Git workbench, Preview, Review, Compare, Research, Handoff, Spawn, clusters, plans, and an in-app manual. The operator chooses providers, models, tools, and whether to enable automation. See the [feature reference](../FEATURES.md) and [operator actions](../OPERATOR_ACTIONS.md).

Native voice setup is available through `npm run voice:setup`. It downloads Moonshine and Vosk recognition models, Parakeet on supported platforms, and Kokoro speech voices at the operator's request. Licenses, versions, hashes, and source URLs are written to `NOTICES.md` in the voice home. The downloads are not redistributed. Docker does not provide microphone capture; voice requires a native installation. Parakeet is skipped on Windows, where Moonshine remains the English recognizer. See [Voice and Computer](../VOICE.md) and [third-party notices](../THIRD_PARTY.md).

## Known limits

- Fresh-install acceptance from the README, native and Docker, remains open. Target-host acceptance on macOS and Windows also remains open; Linux is the current development platform.
- A passing three-OS CI run and the operator's daily-driver trial are required before the `v0.1.0` tag.
- The Vosk English model uses its official versioned download URL and a pinned SHA-256. The publisher does not provide a revision-addressed asset URL, so the URL itself is not immutable; a changed response fails checksum verification before extraction.
- The Moonshine, Kokoro, and Parakeet archives are fetched through the unauthenticated GitHub API, which has a 60-request-per-hour limit per IP address. Voice setup requests three such assets; repeated installations may be rate-limited. Each archive is still checked against its pinned SHA-256.
