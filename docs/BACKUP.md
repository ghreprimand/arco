# Backup & restore

`npx tsx scripts/arco-backup.ts` captures Arco's valuable on-disk state into a single,
dependency-free archive plus a **truthful manifest** that states exactly what was
captured, what was intentionally skipped, and what was redacted. The manifest is
the contract: every regular file in the archive is described by it, and nothing
is silently included or dropped.

Phase F ships in three steps: **F1 `snapshot`, F2 `verify`, F3 `restore`**,
all shipped. See [Restore (F3)](#restore-f3).

```
npx tsx scripts/arco-backup.ts snapshot [--out FILE]
npx tsx scripts/arco-backup.ts verify <FILE>
npx tsx scripts/arco-backup.ts restore <FILE> --into <DIR> [--force-into-live]
```

CLI entry: `scripts/arco-backup.ts`. All decision logic lives in the pure,
side-effect-free modules `scripts/backup/manifest.ts` (capture/skip/redact +
manifest) and `scripts/backup/archive.ts` ((de)serializer). The smoke
(`scripts/smoke/backup-snapshot.ts`, `npm run smoke:backup-snapshot`) imports the
pure functions directly against a fake home, no live server, no real `~/.arco`.

The Arco home defaults to `~/.arco` and honors `ARCO_HOME` (used by tests /
tooling). Output defaults to `<home>/backups/arco-backup-<ISO>.arcobk`.

To migrate data from a compatible earlier installation, copy its home
folder to `~/.arco` (or the folder `ARCO_HOME` names) and each project state
folder to `<project>/.arco`, with both installations stopped. Arco does not
read the earlier installation's home, project state, or backup archives automatically.

## Why this archive format (regular-files-only, gzip + manifest)

Not tar, and not "tar a directory". The format can represent **only regular
files**, a `relPath` plus its bytes. There is nowhere in the wire format to
encode a symlink target, a hardlink, or a special-file type. This eliminates the
entire dangerous-entry class **by construction**: a malicious or corrupt archive
cannot smuggle a symlink/device/fifo through, so F3's restore never has to
defensively reject one (it can't exist). It is also fully portable (pure
`node:zlib`, no `tar` binary, no new npm dependency) and deterministic, so the
smoke round-trips it in memory.

### On-the-wire layout (before gzip)

```
┌────────────┬───────────────────────────┬──────────── entries ───────────┐
│ MAGIC (8B) │ manifestLen (u32 BE) JSON  │ entry · entry · entry · ...      │
└────────────┴───────────────────────────┴────────────────────────────────┘

MAGIC        = ASCII "ARCOBK01" (8 bytes). Wrong magic -> reject.
manifestLen  = uint32 big-endian byte length of the manifest JSON.
manifest     = UTF-8 JSON (BackupManifest), the human-readable contract.
each entry   = relPathLen (u32 BE) · relPath (UTF-8) · byteLen (u32 BE) · bytes
```

The **entire** buffer (header + entries) is gzipped, so a truncated or non-gzip
blob is detected immediately on read, and the manifest lives **inside** the gzip
so it can never drift from the bytes it describes. On read, every `relPath` is
re-validated to reject a leading `/` or any `..` segment (defense in depth for
F3 extraction).

## What is captured, skipped, and redacted

Classification is keyed on the first path segment under the Arco home
(`scripts/backup/manifest.ts › classify()`). The rule is **conservative**: any
path that is not explicitly allowlisted is skipped as `unknown` and recorded,
better to under-capture than to silently sweep in (or leak) something unexamined.

### Captured categories -> source paths

| Category | Source under `~/.arco` (and per-cwd) | Notes |
|---|---|---|
| `globalSettings` | `settings.json` | Captured **with secret-field redaction** (see below). |
| `templates` | `templates.json` | Operator-saved tab templates. |
| `skills` | `skills/` | Operator-authored global skills. |
| `recall` | `recall/` (`recall.db` + `<wfid>/summary.md`) | Retrospective recall projection + summaries. |
| `clusters` | `cluster-presets.json`, `clusters/<id>/` **except** `mailbox/` | Cluster presets + plan/metadata; the live mailbox is skipped (transient). |
| `workflows` | `workflows/` | Any workflow state stored under the home. |
| `knowledge` | `knowledge/` | Operator-curated facts (per-cwd in practice; captured if present under home). |

### Skipped, with reason

| Skipped | Reason | Why |
|---|---|---|
| `auth.json` | `secret` | Claude Native OAuth tokens (`server/src/providers/claude-native/auth.ts`). |
| `provider-accounts/` | `secret` | Codex `CODEX_HOME` credential trees (`server/src/providerAccounts.ts`). |
| `cli-snapshots/`, `llamacpp.json`, `models/`, `camoufox-chatgpt-profile/`, `antigravity-data/`, `checkpoints/`, `known-cwds.json` | `regenerable` | Caches / derived state / downloaded blobs, re-derived by the running server; some are large. |
| `logs/`, `llamacpp.log` | `large-volatile` | Regenerated by the server; large; never valuable to restore. |
| `clusters/<id>/mailbox/**` | `transient` | Budgeted file-per-message drop box, drained on delivery (`docs/GOTCHAS.md § Cluster mode`); restoring it would replay stale/in-flight peer messages. |
| symlink / socket / fifo / device node | `special-file` | Non-regular; not representable in the archive format. The walker uses `lstat` and **never follows symlinks**. |
| anything else under the home | `unknown` | Unrecognized, skipped conservatively so a future `~/.arco` entry is never silently captured or leaked. |

### Secret redaction in `globalSettings`

`settings.json` is captured, but it is parsed and any object key whose **name**
matches `/token|secret|password|api[-_]?key|credential|bearer/i` (at any depth) is
replaced with `"<redacted>"`. The non-secret shape (provider enables, defaults,
theme, Ollama base URL, ...) is preserved. Each redacted field path is recorded in
the manifest's `redactions` array, so the redaction is **documented, not hidden**.
This mirrors the A2 support-bundle allowlist philosophy
(`server/src/diagnostics/supportBundle.ts`): allowlist what is safe, skip-and-
record the rest, and never serialize raw token material.

> **Note, per-cwd state.** Workflow transcripts, plans, tasks, and knowledge
> also live in per-project `<cwd>/.arco/` trees scattered across arbitrary
> working directories. F1's `snapshot` is **home-rooted** (`~/.arco`): it
> captures per-cwd state only if it happens to live under the home. Walking the
> set of known cwds is deliberately out of F1 scope.

## Manifest schema (`BackupManifest`)

```jsonc
{
  "format": "arco-backup/1",
  "arcoVersion": "0.1.0",           // INJECTED (CLI: package.json; smoke: fixture)
  "createdAt": "2026-06-02T...Z",       // INJECTED ISO-8601
  "sourceRoot": "~/.arco",          // home-redacted; informational
  "categories": {                     // each entry == one archive file
    "globalSettings": ["settings.json"],
    "workflows": ["workflows/meta.json"],
    "clusters": ["cluster-presets.json", "clusters/c1/plan.md"],
    "templates": ["templates.json"],
    "skills": ["skills/demo/SKILL.md"],
    "recall": ["recall/recall.db", "recall/<wfid>/summary.md"],
    "knowledge": []
  },
  "skipped": [                        // the honest other half
    { "path": "auth.json", "reason": "secret" },
    { "path": "settings.link.json", "reason": "special-file" }
  ],
  "redactions": [
    { "path": "settings.json", "fields": ["githubToken"] }
  ],
  "fileCount": 7,
  "totalBytes": 1234
}
```

`createdAt` and `arcoVersion` are **injected parameters** of the pure builder,
never read internally, the CLI passes the real version (`package.json`) and
`new Date().toISOString()`; the smoke passes fixed fixture values and asserts
determinism. The pure builder signature:

```ts
buildManifest(input: {
  arcoVersion: string;   // injected
  createdAt: string;       // injected ISO-8601
  sourceRoot: string;
  walk: WalkResult;        // from walkArcoHome()
}): BackupManifest
```

and the writer:

```ts
writeArchive(manifest: BackupManifest, files: ArchiveFile[]): Buffer  // pure
readArchive(gz: Buffer): { manifest: BackupManifest; files: ArchiveFile[] }
```

## Verify (F2)

```
npx tsx scripts/arco-backup.ts verify <FILE>
```

`verify` validates an archive against its **own manifest before any restore
touches the filesystem**, it is the **mandatory gate before F3 restore**. F3
extraction trusts the manifest's category lists; verify is what makes that trust
earned. A tampered, truncated, or incomplete archive fails here with a clear,
readable reason and never reaches restore.

CLI entry: `scripts/arco-backup.ts › doVerify()`. The check logic is the pure,
side-effect-free `verifyArchive(gz: Buffer): { ok: boolean; problems: string[] }`
in `scripts/backup/verify.ts` (Buffer in -> result out; no fs, no clock). The CLI
shell reads the file from disk and calls it. The smoke
(`scripts/smoke/backup-verify.ts`, `npm run smoke:backup-verify`) builds a
known-good archive in memory and a battery of tampered ones, asserting the clean
one passes and each tampered one fails with a meaningful reason.

### What verify checks

`verifyArchive` first delegates the **structural** invariants to `readArchive`
(`scripts/backup/archive.ts`), valid gzip, correct `ARCOBK01` magic, in-bounds
frame lengths (truncation throws), parseable manifest JSON, and safe `relPath`s.
Those throws are caught and turned into a `problems` entry: a corrupt / truncated
/ bad-magic / unsafe-path archive is a verify **failure**, not an exception. On
top of structure it cross-checks the manifest against the actual entries:

- **`format`** is the expected `"arco-backup/1"` (an unknown / forged format
  means the contract can't be trusted -> fail).
- **Required manifest fields** are present and well-typed (`arcoVersion`,
  `createdAt`, `sourceRoot`, `fileCount`, `totalBytes`, `categories`, `skipped`,
  `redactions`).
- **No undeclared (smuggled) file:** every actual archive entry appears in
  `manifest.categories`.
- **No missing file:** every path declared in `manifest.categories` exists as an
  archive entry.
- **`fileCount`** equals the actual entry count.
- **`totalBytes`** equals the summed entry byte lengths.
- **No unsafe entry path** (leading `/` or any `..` segment), defense in depth;
  `readArchive` already throws on these.

Verify **collects all problems** rather than failing fast, so the operator gets
the full list in one pass. The offending paths / expected-vs-actual numbers are
named in each problem string.

### Exit codes

| Exit | Meaning |
|---|---|
| `0` | **OK**, archive matches its manifest. Prints a one-line summary (`fileCount`, `arcoVersion`, `createdAt`). |
| `1` | **FAIL**, one or more problems; each is printed on its own line under a `FAIL` header. |
| `2` | Usage error, missing/extra argument, or the archive file can't be read. |

## Restore (F3)

```
npx tsx scripts/arco-backup.ts restore <FILE> --into <DIR> [--force-into-live]
```

`restore` extracts the archive's **regular files** into `DIR`, **after `verify`
passes**, with safe archive handling from the start. It is **non-destructive by
design**: it never writes into the live Arco home by default, never overwrites
an existing file, and refuses anything that could escape the target tree.

CLI entry: `scripts/arco-backup.ts › doRestore()`. The testable security core is
split into two pure-ish functions in `scripts/backup/restore.ts`:

```ts
planRestore(gz: Buffer, targetRoot: string): RestorePlan   // PURE, no fs writes
applyRestore(plan: RestorePlan, targetRoot: string): RestoreResult  // the ONLY effecting fn
```

`planRestore` runs the verify gate, path-safety, traversal, and cap checks with
**no fs access**; `applyRestore` is the single side-effecting function (symlink-
component refusal, mkdir, `wx` writes). The smoke
(`scripts/smoke/backup-restore.ts`, `npm run smoke:backup-restore`) hammers both
against temp dirs: happy path, verify-first refusal, traversal rejection, the
symlink-in-target refusal, never-overwrite, and the cap abort.

### Why restore needs guards even though the format is regular-files-only

The F1 format eliminates dangerous *archive entries* by construction, there is
nowhere on the wire to encode a symlink/hardlink/special file, and `readArchive`
re-rejects an unsafe `relPath` on read. So restore's job is guarding the **target
tree** and the **extraction**, not the entries:

1. **verify-first (mandatory).** `planRestore` runs `verifyArchive` and refuses the
   **whole** restore on any problem, a tampered/truncated/incomplete archive
   never reaches the filesystem.
2. **Symlink components in the target.** The archive can't carry a symlink, but
   `DIR` might already contain a symlinked directory (attacker-planted, or a
   pre-existing `~/.arco` symlink). Writing `foo/bar` where `foo -> /etc` escapes
   the root. `applyRestore` `lstat`s **every** intermediate path component and
   **refuses to descend through any that is a symlink** (records it rejected,
   never follows it). A non-directory sitting where a directory is needed is also
   refused rather than clobbered.
3. **Traversal (defense in depth).** `planRestore` re-rejects absolute / `..` /
   empty / `.` `relPath`s (splitting on both `/` and `\`), then computes the
   resolved absolute target and asserts it stays **strictly within**
   `resolve(targetRoot) + separator` (normalized-prefix check), a path that
   survives the naive segment check but still resolves outside the root is caught
   here.
4. **Never overwrite.** Files are written with the `wx` flag (`O_CREAT | O_EXCL`):
   an existing target makes the write fail with `EEXIST` -> it is recorded as
   **skipped**, never clobbered. The operator's local edits survive.
5. **Resource caps.** `MAX_FILES` (50 000) and `MAX_TOTAL_BYTES` (2 GiB). Breaching
   **either** aborts the **whole** run (no partial extraction), a maliciously
   inflated manifest can't make restore write an unbounded amount.

### Non-destructive default

`--into <DIR>` is **required** and **must not already exist**, a fresh directory
means restore can't silently merge into (or partially overwrite) a live tree. The
operator inspects `DIR` and moves files into place manually.

Restore **refuses** a target that *is* or is *inside* the live Arco home
(`ARCO_HOME` or `~/.arco`) unless `--force-into-live` is passed. The default
is to refuse; the override is documented but discouraged. (This refusal lives in
the CLI, which knows the live home; `planRestore`/`applyRestore` are home-agnostic
and operate purely on the `targetRoot` they are handed.)

### Exit codes

| Exit | Meaning |
|---|---|
| `0` | Restored cleanly, some entries may be **skipped** (already existed); printed. |
| `1` | **Refused / partial**, verify failed, a cap was breached, the target is the live home (no `--force-into-live`), the target already exists, **or** any entry was rejected (a rejection is surfaced as non-zero so a scripting operator notices a partial result). Reasons are printed. |
| `2` | Usage error, missing `<FILE>` / missing `--into` / extra argument, or the archive file can't be read. |
