## 2026-10-25 -- Hosted CI workflow and browser smoke runner

Pushes to `main` and pull requests now run `.github/workflows/ci.yml` on Linux, macOS and Windows runners with Node 24. Each runner installs with `npm ci --include=dev`, then runs `npm run build`, `npm run typecheck`, `npm run test:unit`, `npm run audit:public -- --tree` and `npm run docs:check`. The Linux runner also runs `node scripts/public-audit.mjs --history` on a full-depth checkout, which checks identity and trailers across history. Line-ending conversion is disabled before checkout so the byte-exact Phosphor palette hash test sees LF files on Windows.

A new `npm run smoke:browser` (`scripts/smoke/run-browser-suites.mjs`) starts one Vite dev server per Playwright script on the port that script expects and runs five suites: phosphor-demo, computer-panel, deepseek, operator-questions and voice-scroll. All API and WebSocket traffic is fulfilled inside the scripts, so no provider or credential is involved. A Linux job runs them as blocking; macOS and Windows run the same suites as non-blocking. A Docker job builds the image only if a `Dockerfile` exists, so it stays inert until the container baseline lands.

Checked locally: the workflow parses as YAML, the five suites pass against Chromium on this host (5 of 5), and the history audit passes in a fresh clone. Three browser scripts are excluded and listed in the runner: help-docs searches for manual text absent from the tree (also absent upstream), voice times out after the scrub renamed its fixture cluster, and phosphor-production sees an unexpected non-GET `/api/session` call. Their fixes are board findings, not workarounds. Not verified: any hosted run, since the workflow only executes after push; macOS and Windows failures are expected and feed the platform work. The link check is left as a comment until the documentation set provides it.

## 2026-10-25 -- Import of the upstream workbench tree

The Arco tree was imported from the private upstream at a pinned revision. Arco adds public-facing branding and a new-user entry point while preserving the workbench behavior and internal compatibility.

The import excluded 91 files: 86 of 122 docs containing planning, research, audit, validation, or archive history, plus five private or replaced root files. It retained 36 reference docs. User-facing Archon names became Arco; `@archon/*`, `.archon`, protocol identifiers, MCP names, `ARCHON_*` variables, and bracketed model markers remain Archon-compatible. `ARCO_*` aliases take precedence. No recordings, screenshots, transcripts, or real-provider fixtures were found.

The scrub changed 29 home-path files, 39 personal-name files, 51 private-host or network-identity files, 28 hostname-bearing theme files, 43 private-project-name files, six private-repository-URL files, and 21 workstation-default files. Categories overlap. Thirty-three test or smoke files changed for privacy; one theme snapshot hash changed after theme identifiers were renamed.

`npm run setup:hooks` installs identity, `.githooks`, and unsigned-commit settings. Hook fixtures reported 26 passes and one optional Docker/Gitleaks skip. `npm run build`, `npm run typecheck`, `npm run test:unit` (757 passed), `npm run audit:public --tree`, all 28 upstream `test:*` scripts (0 skips), and 12 server-free smokes passed. An initial install omitted dev dependencies under `NODE_ENV=production`; `env -u NODE_ENV npm ci --include=dev` resolved it. Voice tests needed the Arco return phrase, and a template fixture needed consistent lowercase naming.

Theme ids whose leading word was a hostname were renamed; saved Archon theme ids are mapped onto the Arco ids on the settings read path (`normalizeLegacyThemeId` in the shared `themes.ts`, covered by `themeLegacy.test.ts`), so a theme chosen in Archon still resolves in Arco. Open: 40 imported docs still contain em-dashes, some docs link to excluded planning docs, `npm run size:check` cites an excluded doc, server-backed smoke suites were not run, and the `NODE_ENV=production` install caveat needs a line in the getting-started guide. macOS and Windows acceptance and Docker onboarding remain open. No paid provider calls or credential copies were used.
