## 2026-10-25 -- Cross-platform voice setup with verified downloads and notices

`npm run voice:setup` now runs `scripts/voice/run.mjs`, which checks for uv and starts `scripts/voice/setup.py` with `uv run --no-project --python 3.12`. A system `python3` is no longer needed, which matters on Windows, where `python3` is usually absent. `setup.py` resolves the voice home as `ARCO_VOICE_HOME`, then `ARCHON_VOICE_HOME`, then `voice` inside `ARCO_HOME`, `ARCHON_HOME` or `~/.archon`. It uses `venv\Scripts\python.exe` on Windows and streams each model archive while hashing it against a pinned SHA-256 (Moonshine tiny, Kokoro multi-language v1.0, the Vosk small US English model, Parakeet v3 int8). A mismatch aborts before unpacking. Parakeet is still skipped on Windows. Each run writes `NOTICES.md` in the voice home and prints it: every model with license, upstream and checksum (including the GPL-3.0-or-later espeak-ng data inside the Kokoro archive and CC-BY-4.0 for Parakeet), the uv-provided Python runtime, and every package in the voice venv with its declared license. `scripts/voice/check-phrases.py` uses the same home resolution and the Windows interpreter path. `docs/VOICE.md` describes setup, the home, checksums and notices.

Checked on Linux in a temporary `ARCO_HOME`: a first `npm run voice:setup` installed 14 Python packages and about 985 MB of models and wrote the notices; a second run skipped every model. With `ARCHON_VOICE_HOME` pointed at it, `npm run smoke:voice` passed 6/6, including in-memory recognition of sample audio and WAV speech output. `check-phrases.py` round-tripped Kokoro-spoken phrases through Parakeet and Vosk ("End capture", "Cancel capture"). The pinned hashes came from a separate download of the same release assets.

What failed: the first hash download stalled near the end of the Parakeet archive and was resumed.

Open: macOS and Windows runs, and a microphone round-trip through the Computer panel, belong to the acceptance passes. Until the Arco home change lands, the server reads only `ARCHON_VOICE_HOME` or `~/.archon/voice`.

## 2026-10-25 -- npm start, the Node requirement and native install notes

`npm start` now runs a built Arco in the foreground on every platform: `scripts/start.mjs` checks that `server/dist` and `client/dist` exist (otherwise it asks for `npm run build`), sets `ARCHON_SERVE_CLIENT=1` and `NODE_ENV=production` unless they are already set, and runs `server/dist/index.js` from the repository root, serving the client on http://localhost:3001. This replaces setting those variables in a POSIX shell, which does not work in PowerShell. The root `package.json` declares `engines.node >=24`, the version the Docker image and this host use.

`docs/OPERATIONS.md` now lists the native requirements (Node 24, npm, Git, a C/C++ toolchain with Python 3 for `better-sqlite3` and `node-pty` when no prebuilt binary matches), explains that an exported `NODE_ENV=production` makes `npm ci` skip dev dependencies and how to install anyway on POSIX shells and PowerShell, adds a platform table (Arco home location, default terminal shell, launcher and service support), documents `npm start`, rewrites the `ARCHON_HOME` row for the whole-home relocation and adds `ARCHON_TEST_CHROME` for the Python browser smokes. `npm run size:check` no longer points at an excluded planning document; it still reports the same oversized files Archon has.

Checked: `npm start` with a temporary home on port 3098 reached `/readyz` and served the client title; `npm run build`, `npm run typecheck`, `npm run test:unit` and `npm run audit:public` pass.

What failed: two diagnostics smokes were run during the audit without a temporary server; they reached the default port, got 401 from the running instance and changed nothing. Server-backed smokes need `ARCHON_SMOKE_WS_URL` pointing at a temporary server.

Open: macOS and Windows runs of `npm run dev` and `npm start` are part of the real-host acceptance.
