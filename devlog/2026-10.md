## 2026-10-25 -- ARCO_HOME relocates the whole Arco home

Setting `ARCO_HOME` (or the internal `ARCHON_HOME`) now moves every global store, not only the MCP registry and the backup source. The new `server/src/archonHome.ts` returns `ARCHON_HOME` resolved to an absolute path when it is set and non-empty, else `.archon` under the user home (`~/.archon` on Linux and macOS, `%USERPROFILE%\.archon` on Windows, the location Archon already used). `envAliases.ts` copies `ARCO_HOME` onto `ARCHON_HOME` first, so the Arco name wins. Fifty server modules that joined the user home with `.archon` (settings, provider accounts and secrets, clusters, chats, checkpoints, bake-offs, worktrees, recall index, skills, prompts, templates, logs, pid registries, voice stores and the remaining stores) now call it, as do the `archon-agent`, `archon-service` and `archon-management` CLIs, the management vault and agent identity. `scripts/antigravity-oauth.mjs` reads `ARCO_HOME`, then `ARCHON_HOME`, itself. Per-project `.archon` directories are unchanged.

Checked: `archonHome.test.ts` covers the default, a relative override and an empty value. `npm start` in a temporary home with `ARCO_HOME` pointed at a subfolder wrote settings, clusters, the instance id and CLI snapshots only there and created no `.archon` in the home. `npm run test:unit` passed; the server-free smokes `mcp-registry`, `task-board`, `templates`, `cluster-vault`, `backup-snapshot`, `backup-verify`, `backup-restore`, `purge`, `checkpoints`, `recall-index`, `notifications`, `project-trust`, `operator-skills`, `prompt-commands`, `file-write`, `sensitive-write` and `debag-gate` passed in temporary homes.

What failed: the first mechanical pass also rewrote the helper's own default into a self-call, and it collided with the registry's local helper of the same name; both were fixed before typecheck passed.

Open: the voice setup scripts still default to `~/.archon/voice` without consulting `ARCO_HOME`; that is part of the voice item.
